## Implemented and verified

- Attach the actual WindowStage main window; manager lookup/enumeration and the
  generated C ABI return that window. Repeated wrapping shares its stable identity.
- Create an actual child through the asynchronous WindowStage API, load its ArkUI
  content and register it with the correct parent. The synchronous `Window()`
  constructor stays invalid on OHOS; it does not pretend to create a native window.
- Move/resize in logical coordinates and compare with the public NDK's pixel
  geometry. Read real drawable content bounds; reject non-finite/invalid geometry.
- Set native focusability and touchability, preserve state after unsupported input
  forwarding requests, show without activation, focus, blur back to the prior main
  window, hide and show again. Hit-test attached window ordering and exclusion.
- Deliver real native creation/rectangle/focus/destruction events to the manager and
  per-window subscriptions on the ArkTS UI thread, including duplicate wrappers.
- Cancel a close, defer approval from a worker thread and coalesce repeated requests.
  Native destruction invalidates all wrappers and removes manager lookups. Retained
  wrappers safely reject later operations. Ability-owned main windows reject Close.
- Stop monitoring when the last observer is removed, restart it for another child,
  and invalidate identities when the host destroys a window directly.
- Report content-loading failure once and dispose the hidden child. A created-event
  listener can immediately close its new window without leaking it or losing the
  factory completion.
- Enable and restore immersive content layout on the actual main window. Enter
  and exit full screen, restore system bars, and verify the getter and exactly-once
  full-screen events agree.

The x86_64 emulator can report its outer rectangle before drawable layout and
geometry notifications are ready. The fixture waits for those actual conditions,
with its existing deadline, rather than treating a submitted setter as completion.
HiLog checks are logged individually, with a short final marker to avoid truncating
large result reports.

## Host integration and scope

The platform-internal seam is `core/src/platform/ohos/ohos_window.h`:
`AttachWindowStage`, `AttachWindow` and asynchronous `CreateSubWindow`. The host
retains ownership of its Ability, stage and native windows; nativeapi holds borrowed,
invalidatable identities. Window wrappers and existing language bindings use the
same linked nativeapi instance. See `core/src/platform/ohos/README.md` for the host
example and the exact lifecycle/permission rules.

Geometry/status observers are managed lazily; a lifecycle observer remains attached
for native invalidation. Environment cleanup releases references without executing
JavaScript during teardown. Actual environment teardown was reviewed in code; it
is not a separate emulator assertion in this suite.

Device/window-type restrictions still apply to maximize/recover, size limits,
decorations/title, topmost and shadows; those device-specific paths were not
validated on a desktop-form-factor HarmonyOS device. Privacy mode requires normal
PRIVACY_WINDOW authorization. System title-bar close handlers remain with the host;
cancellable nativeapi Close covers programmatic child-window requests. Hit testing
cannot inspect other applications. Reparenting, input forwarding, opacity, arbitrary
shape, native content views and desktop drag/resize gestures remain unsupported.
